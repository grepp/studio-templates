# Template Update Guide

이 문서는 템플릿 버전 업데이트가 감지되었을 때 AI Agent가 따라야 할 업데이트 절차를 정의한다.

---

## 업데이트 절차

### 1. 변경 파일 확인

원격에서 최신 템플릿 파일을 fetch하여 로컬 파일과 비교한다:

```bash
BASE_URL=https://raw.githubusercontent.com/grepp/studio-templates/refs/heads/main/docs
```

**비교할 파일:**

| 파일 | 로컬 경로 | 업데이트 전략 |
|------|-----------|--------------|
| AGENTS.md | `./AGENTS.md` | **덮어쓰기** — 운영 표준 문서이므로 항상 최신 버전으로 교체 |
| ARCHITECTURE.md | `./.grepp-agent/ARCHITECTURE.md` | **병합** — 프로젝트 고유 내용 보존, 구조/섹션 변경만 반영 |
| RUNBOOK.md | `./.grepp-agent/RUNBOOK.md` | **병합** — 프로젝트 고유 내용 보존, 절차/섹션 변경만 반영 |
| SECURITY.md | `./.grepp-agent/SECURITY.md` | **병합** — 프로젝트 고유 내용 보존, 정책/섹션 변경만 반영 |

### 2. AGENTS.md 업데이트 (덮어쓰기)

AGENTS.md는 AI 작업 기준 문서이므로 원격 버전으로 그대로 덮어쓴다.
이 파일은 사용자가 직접 수정하지 않는다.

### 3. .grepp-agent/ 파일 업데이트 (병합)

각 파일에 대해 다음을 수행한다:

1. 원격 템플릿을 fetch한다
2. 로컬 파일과 원격 템플릿을 비교한다
3. **구조적 변경** (새로운 섹션, 섹션 순서 변경, 필드 추가 등)은 반영한다
4. **프로젝트 고유 내용** (서비스명, 담당자, 실제 데이터 등)은 보존한다
5. `TODO:` 항목이 새로 추가된 경우, 기존에 채워진 값은 유지하고 새 항목만 `TODO:`로 남긴다

**병합 원칙:**
- 원격에 새로운 섹션이 추가되면 → 로컬에도 추가
- 원격에서 섹션이 삭제되면 → 사용자에게 확인 후 삭제
- 원격에서 섹션 내용(지침, 기준)이 변경되면 → 로컬에 반영
- 로컬의 `TODO:`가 채워진 값 → 절대 덮어쓰지 않음

### 4. 사용자 보고

업데이트 전 사용자에게 다음을 보고하고 동의를 구한다:

```
🔄 템플릿 업데이트가 감지되었습니다.

현재 버전: {로컬 VERSION}
최신 버전: {원격 VERSION}

변경사항:
- AGENTS.md: {변경 내용 요약}
- ARCHITECTURE.md: {변경 내용 요약}
- RUNBOOK.md: {변경 내용 요약}
- SECURITY.md: {변경 내용 요약}

업데이트를 적용하시겠습니까?
```

### 5. 업데이트 적용

사용자가 동의하면:

1. AGENTS.md를 원격 버전으로 덮어쓴다
2. .grepp-agent/ 파일들을 병합 규칙에 따라 업데이트한다
3. `.grepp-agent/VERSION` 파일을 원격 버전으로 갱신한다
4. 변경된 파일 목록을 사용자에게 보고한다

사용자가 거부하면:

- 현재 상태를 유지한다
- 다음 세션에서 다시 확인한다
- `.grepp-agent/VERSION`은 변경하지 않는다

### 6. 업데이트 후 검증

업데이트 적용 후 다음을 확인한다:

- 모든 파일이 정상적으로 존재하는지
- 프로젝트 고유 내용이 보존되었는지
- 새로운 `TODO:` 항목이 있는 경우 사용자에게 안내
