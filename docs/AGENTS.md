# AI Agent Development Guide

## 1. 목적

이 문서는 비개발자 또는 AI를 활용하여 생성된 코드를  
회사 운영 표준에 맞는 형태로 리팩토링하고,  
운영 가능한 서비스로 전환하기 위한 가이드이다.

AI는 본 문서를 기준으로 다음을 수행해야 한다:

- 코드 구조 정리
- 보안 기준 적용
- 실행 및 배포 환경 구성
- 필수 문서 생성

## 3. 기술 표준

### 3.1 실행 환경 (Docker 강제)
- **모든 프로젝트는 Docker 기반으로 실행 가능해야 한다** — 예외 없음
- 서버 애플리케이션: 앱 서버 컨테이너로 빌드
- 정적 파일 프로젝트(HTML/JS/CSS): Nginx 등으로 정적 호스팅하는 컨테이너로 빌드
- `docker build` 및 `docker run` 한 번에 실행 가능하도록 구성한다

### 3.2 운영 환경
- 서버가 있는 프로젝트: **Kubernetes (Helm)** 기준으로 구성한다
- 정적 파일 프로젝트: 컨테이너 배포 후 **Kubernetes (Helm)** 또는 정적 호스팅(S3 / CloudFront) 기준으로 구성한다

### 3.3 데이터베이스
- DB가 필요한 프로젝트는 **PostgreSQL 16.x 기준**으로 구성한다
- DB 연결은 민감정보 분리 파일을 통해 처리한다

### 3.4 언어
- Python 또는 Ruby 기반을 권장한다
- 기타 언어 사용 시 실행 방법을 명확히 문서화한다

## 4. 보안 표준

### 4.1 금지사항
- 비밀번호, API Key, 토큰, 인증정보를 코드에 직접 포함하지 않는다
- DB 접속정보를 코드 또는 문서에 평문으로 저장하지 않는다

### 4.2 민감정보 분리

모든 민감정보(API Key, 비밀번호, 토큰, DB 접속정보)는 코드에서 분리한다.
실행 환경에 따라 적절한 방식을 선택한다:

| 환경 | 분리 방식 | 예시 파일 | 실제 파일 (.gitignore 등록) |
|------|-----------|-----------|---------------------------|
| 서버 런타임 (Node.js, Python 등) | 환경 변수 파일 | `.env.example` | `.env` |
| 브라우저 only (HTML/JS) | JS 설정 파일 | `app-config.example.js` | `app-config.js` |
| 브라우저 only (대안) | JSON 설정 파일 | `config.example.json` | `config.json` |
| 빌드 도구 사용 (Vite, webpack 등) | `.env` + 빌드 주입 | `.env.example` | `.env` |

**원칙:**
- 예시 파일(`.example`)은 dummy 값으로 Git에 커밋한다
- 실제 파일은 `.gitignore`에 등록하여 커밋하지 않는다
- 기존 프로젝트가 이미 분리 방식을 사용 중이면 그 방식을 유지한다
- **프로젝트 환경에 맞는 방식 하나만 선택**하여 적용한다. 여러 방식을 중복 생성하지 않는다
  - 예: HTML-only 프로젝트에 `app-config.example.js`를 선택했으면 `.env.example`은 생성하지 않는다

**분리 방식:**
- 소스 코드에서 민감값을 추출하여 **참조(변수/설정 파일 로드)**로 대체한다
- 소스 코드는 참조만 남고 더 이상 실제 값을 포함하지 않는다
- 예시 파일(`.example`)에는 dummy 값(예: `your-api-key-here`)을 넣는다
- **실제 파일에 소스 코드에서 추출한 기존 값을 그대로 넣는다. 절대 삭제하지 않는다.**
- 앱은 실제 파일이 있으면 즉시 동작해야 한다

**사용자 안내 (필수):**
완료 보고 시 사용자에게 다음을 반드시 안내한다:
- 기존에 Git에 커밋된 민감정보(API Key, 비밀번호 등)가 있으면 **해당 값을 즉시 재발급**받아야 한다
- 재발급 후 실제 파일(`.env`, `app-config.js` 등)의 값을 새 값으로 교체해야 한다
- 실제 파일은 `.gitignore`에 등록되어 있으므로 Git에 커밋되지 않는다

### 4.3 인증 및 권한
다음 중 하나에 해당하면 인증 구조를 추가한다:

- 여러 사용자가 접근하는 경우
- 데이터 조회/수정 기능이 있는 경우

가능한 경우:
- 기본 인증 구조 (JWT, Session 등) 추가
- 관리자 / 일반 사용자 구분

### 4.4 로그 보안
- 로그에 다음 정보가 포함되지 않도록 한다:
  - 개인정보
  - 인증 토큰
  - 비밀번호

## 12. 템플릿 버전 관리

### 세션 시작 시 버전 확인

사용자의 **첫 번째 요청**을 받으면, 본격적인 작업에 앞서 **반드시** 다음 절차를 수행한다:

1. **로컬 버전 확인**:
   ```bash
   cat .grepp-agent/VERSION
   ```
   - 파일이 없으면 템플릿이 설치되지 않은 것이다 → 설치 가이드(`installation.md`)를 안내한다

2. **원격 버전 확인**:
   ```bash
   curl -s https://raw.githubusercontent.com/grepp/studio-templates/refs/heads/main/docs/VERSION
   ```

3. **버전 비교**:
   - 원격 버전 > 로컬 버전 → 업데이트 절차 진행
   - 동일 → 아무 작업 없이 사용자 요청을 처리한다

### 업데이트 절차

새 버전이 감지되면:

1. **업데이트 가이드 fetch**:
   ```bash
   curl -s https://raw.githubusercontent.com/grepp/studio-templates/refs/heads/main/docs/update.md
   ```

2. update.md의 지시에 따라 변경 파일을 비교하고 업데이트를 적용한다

3. 사용자에게 변경 내역을 보고하고 동의를 구한 후 실행한다

4. 업데이트 완료 후 `.grepp-agent/VERSION`을 새 버전으로 갱신한다
